# 色彩去噪：CCD 与 Cnr4

[返回知识目录](README.md) · [CCD API](../../api/zh-CN/ccd.md) · [Cnr4 API](../../api/zh-CN/cnr4.md)

## CCD：用颜色差异选择空间点

CCD 检查稀疏的空间采样点。RGB 的距离为三通道差的平方和；YUV 的距离为 `4*ΔY²+ΔU²+ΔV²`，亮度变化对是否混合具有更大影响。

原始点集如下，括号为相对中心的 `(x,y)`：

| 组 | 点集 |
|---|---|
| 近，4 点 | `(±4,±4)` |
| 中，8 点 | `(±8,±8)`、`(0,±8)`、`(±8,0)` |
| 远，12 点 | y=±12 时 x=−12、−4、4、12；y=±4 时 x=±12 |

YUV 按抽样缩小坐标，再按 scale 缩放并取整；越界位置使用镜像坐标。参考亮度经 Bilinear 对齐到色度尺寸。RGB 处理三个输出平面，YUV 保留主片亮度，仅更新色度。

设格式最大值为 M（浮点为 1），参数阈值 t 对应内部门槛：

```text
T = (t*M)^2 / (255^2*3)
```

距离严格小于相应门槛时才接受该点。整数路径还对距离项和门槛作规定的取整，不应把它解释为“每通道差小于 t”。

temporal_radius=0 时只利用当前参考帧。半径增大时，会把其他时间帧中候选位置到**当前参考帧中心**的距离纳入判定，并施加时间权重。前、后方向使用的权重公式并不完全相同，不能改写为简单对称时间均值。

无论判定用了多少时间帧，被选中后加入输出平均的都是当前主片中该空间位置的像素。中心像素始终参与。由此可见，扩大时间半径与扩大输出平均的帧数是两件不同的事。

ref 可用预处理结果提供较稳定的差异信息，但输出颜色仍取自主片。参考过度模糊也可能让原本不同的区域更容易通过门槛。

## Cnr4：根据 Y/U/V 差异控制时间混合

Cnr4 仅处理整数 YUV。比较当前与时间邻帧的参考亮度差及相应色度差，查表后组合成混合权重；权重越大，邻帧对输出色度的贡献越大。亮度虽然不被输出修改，仍会影响色度混合。

三个 mode 字符分别选择 Y/U/V 的曲线，并不是处理开关。设 8 位差异索引为 l，sense 为 s：

```text
o: base = (1 + cos(l*l*pi/(s*s))) / 2
x: base = (1 + cos(l*pi/s)) / 2
table[l] = floor(clamp(str * base^(1/pow), 0, 255))
```

表只在实现规定的 `0…str` 索引范围内填充，其余为 0。sense=0 与 pow=0 有专门边界处理，不能直接代入除法公式。由于曲线与有效索引范围同时受参数控制，不能笼统地说 sense 或 str 增大时每个差异位置都会单调增强。

tmode 0 对邻帧直接做一遍处理。1–4 从时间窗口两端向内进行预处理，区别在于是否逐步扩大局部半径，以及是否同时更新后续使用的源像素。它们不依赖上一帧输出作为全局递归状态，但每个窗口内部会有多遍处理成本。

距离为 k（最近帧 k=1）、半径为 r 时，时间权重为：

| wmode | 权重 |
|---|---|
| 0 | 1 |
| 1 | `sqrt((r-k+1)/(2r))` |
| 2 | `sin((r-k+2)/(2r))`，弧度 |
| 3 | `1/(k+1)` |

这些时间权重再作用于差异权重；不是把结果统一乘一个亮度系数。主片场景属性决定窗口中的哪些样本应被中心替代，见[时间边界](shared/temporal-boundaries.md)。
